# Firing Range

> **Учебный проект.** Сделан в рамках задания Firing Range, коммерческим продуктом
> не является. Код написан и прокомментирован так, чтобы по нему было видно, как
> устроены системы шутера от первого лица, а не так, чтобы было покороче.

**Движок:** Unreal Engine 5.5
**Язык:** только C++, без Blueprints
**Платформы:** Windows, Linux, macOS

*[English version](README.en.md)*

### Авторы

| Автор | Зона ответственности |
|---|---|
| **zutemiss** | Каркас проекта и конфигурация движка, базовые типы и сохранения, персонаж и система ввода, вся система оружия, баллистика и физика снарядов, ящики с патронами, правила сессии и подсчёт точности |
| **dshadykh** | Мишени и зоны попадания, ИИ движущихся мишеней и маршруты патрулирования, HUD, все меню на Slate, процедурная постройка тира, документация |

Разделение видно в истории коммитов: `git shortlog -sne` и `git log --author=...`.

Тир от первого лица: три ствола, физические пули, статичные и движущиеся мишени
под управлением ИИ, ящики с патронами, HUD с точностью стрельбы, главное меню на
отдельной карте, пауза и режим на время.

## Готовая сборка

Собранная игра для Windows лежит в репозитории на **GitHub**. Туда, а не на
школьный Gitea, — потому что архив весит около 260 МБ, а Git LFS, который нужен для
таких файлов, на Gitea выключен.

| | |
|---|---|
| **Страница файла** | https://github.com/UZhomart/firing-range/blob/main/Release/FiringRange-Win64.zip |
| **Прямая ссылка** | https://github.com/UZhomart/firing-range/raw/main/Release/FiringRange-Win64.zip |
| **Размер** | 260 МБ в архиве, 380 МБ после распаковки |
| **Конфигурация** | Shipping, Windows 64-bit |

> Сборка только для Windows. Про macOS и Linux — в разделе
> [Другие платформы](#другие-платформы).

### Как запустить

1. Скачать архив по прямой ссылке — или открыть страницу файла и нажать значок
   загрузки справа (**Download raw file**).
2. Распаковать: правый клик по архиву → **Извлечь всё…** → **Извлечь**.
3. Открыть появившуюся папку `FiringRange-Win64` и запустить **`FiringRange.exe`**.
4. Если Windows покажет окно *«Система Windows защитила ваш компьютер»* — нажать
   **Подробнее** → **Выполнить в любом случае**. Сборка не подписана цифровой
   подписью, поэтому фильтр SmartScreen её не знает.
5. Если появится ошибка про `MSVCP140.dll` или `VCRUNTIME140.dll` — в той же
   папке запустить `Engine\Extras\Redist\en-us\UEPrereqSetup_x64.exe`. Он
   установит недостающие библиотеки Microsoft. После этого снова запустить
   `FiringRange.exe`.

### Что нужно на компьютере

- Windows 10 или 11, 64-bit
- Видеокарта с поддержкой DirectX 11 или 12 и актуальный драйвер

Unreal Engine и Visual Studio для запуска сборки **не нужны**. Они нужны только
для работы с исходным кодом — об этом разделы ниже.

## Установка

### 1. Visual Studio 2022

Скачать по ссылке выше → запустить `VisualStudioSetup.exe` → в окне выбора
компонентов отметить две рабочие нагрузки:

- ☑ **Разработка игр на C++** (Game development with C++)
- ☑ **Разработка классических приложений на C++** (Desktop development with C++)

Больше ничего отмечать не нужно. Нажать **Установить**.

> Порядок важен: установщик Unreal при запуске ищет компилятор MSVC. Если
> Visual Studio ещё нет, движок встанет без поддержки C++.

### 2. Unreal Engine 5.5

1. Скачать и установить **Epic Games Launcher** по ссылке выше.
2. Войти под аккаунтом Epic.
3. Слева выбрать вкладку **Unreal Engine**, сверху — **Library**.
4. В разделе *Engine Versions* нажать жёлтый **`+`**.
5. На появившемся слоте нажать **стрелочку вниз** рядом с номером версии и
   выбрать **5.5.x** — по умолчанию предлагается более новая версия, она не
   подойдёт.
6. Нажать **Install**, затем в открывшемся окне — ссылку **Options**, и снять
   галочки: *Starter Content*, *Templates and Feature Packs*, *Engine Source*, а
   также все платформы кроме Windows.
7. Установить.

> **Если список Engine Versions пустой** и кнопка **Install Engine** ничего не
> делает на только что созданном аккаунте Epic — подождите несколько часов.
> Доступ к движку новым аккаунтам выдаётся с задержкой.

### 3. Проект

```bash
git clone https://01.tomorrow-school.ai/git/zutemiss/firing-range.git
cd firing-range
```

Двойной клик по **`FiringRange.uproject`**. Редактор спросит, собрать ли
недостающие модули — ответить **Yes**. Первая компиляция занимает 5–15 минут.

> **Если Windows спрашивает «Как вы хотите открыть этот файл?»** — ничего не
> выбирайте и закройте окно крестиком. Это значит, что файлы `.uproject` не
> связаны с Unreal. Откройте проект командой из раздела
> [Запуск игры](#5-запуск-игры) — способ Б.

### 4. Две карты

Карты уже лежат в репозитории: `Content/Maps/MainMenu.umap` и
`Content/Maps/FiringRange.umap`. Обе **пустые** — всё их содержимое строится
кодом при запуске, — и каждой назначен свой режим игры.

Делать ничего не нужно. Шаги ниже — только если карты по какой-то причине
пропали.

**Восстановить скриптом:** запустить редактор так, чтобы скрипт выполнился сам:

```powershell
& "C:/Program Files/Epic Games/UE_5.5/Engine/Binaries/Win64/UnrealEditor.exe" `
  "<путь-к-проекту>/FiringRange.uproject" `
  -ExecutePythonScript="<путь-к-проекту>/Scripts/GenerateMaps.py"
```

Или в уже открытом редакторе: `Window → Output Log`, переключить консоль внизу в
режим **Python** и выполнить:

```python
exec(open(r"<путь-к-проекту>/Scripts/GenerateMaps.py").read())
```

**Восстановить вручную:**

1. `File → New Level → Empty Level` → `File → Save Current Level As…` →
   `Content/Maps/MainMenu`
2. Повторить, сохранить как `Content/Maps/FiringRange`

### 5. Запуск игры

Есть два способа. Команды ниже — для PowerShell и для движка, установленного в
папку по умолчанию. Если путь к проекту другой, замените
`C:\Users\python\Desktop\firing-range` на свой.

#### Способ А — сразу игра, без редактора

Игра открывается отдельным окном, как обычная игра. Первым показывается главное
меню.

```powershell
& "C:\Program Files\Epic Games\UE_5.5\Engine\Binaries\Win64\UnrealEditor.exe" "C:\Users\python\Desktop\firing-range\FiringRange.uproject" -game -windowed -ResX=1280 -ResY=720
```

Флаг `-game` запускает проект в игровом режиме, `-windowed -ResX -ResY` задают
окно 1280×720. Чтобы не вводить команду каждый раз, можно сделать ярлык:
правый клик на рабочем столе → **Создать → Ярлык** → вставить эту же строку без
`& ` в начале → **Далее** → имя `Firing Range` → **Готово**.

#### Способ Б — через редактор

1. Открыть проект в редакторе:

   ```powershell
   & "C:\Program Files\Epic Games\UE_5.5\Engine\Binaries\Win64\UnrealEditor.exe" "C:\Users\python\Desktop\firing-range\FiringRange.uproject"
   ```

2. Дождаться, пока откроется окно редактора. При первом запуске справа внизу
   идёт счётчик *Compiling Shaders* — это может занять 10–40 минут.
3. Нажать зелёный треугольник **▶ Play** на верхней панели (или `Alt+P`).
4. Остановить игру — `Esc`, затем кнопка **■ Stop** на верхней панели.

#### Что происходит дальше

1. Открывается главное меню **FIRING RANGE** — отдельная карта `MainMenu`.
2. Кнопка **START GAME** загружает карту `FiringRange`, и игровой режим строит
   весь тир до того, как появится персонаж.
3. Выход: `Esc` → **MAIN MENU** → **QUIT**.

В редакторе ничего назначать не нужно: ни одного Blueprint создавать не надо, ни
одного класса в выпадающих списках выбирать не надо, ни одного актора на уровень
перетаскивать не надо.

#### Если компьютер слабый

На встроенной видеокарте или при 8 ГБ памяти в редакторе стоит снизить качество:
кнопка **⚙ Settings** справа вверху → **Engine Scalability Settings** → **Low**.
Для способа А можно добавить в конец команды `-ExecCmds="scalability 0"`.

## Другие платформы

Готовая сборка из раздела выше — **только для Windows**. На macOS и Linux она не
запустится.

### macOS

Сделать отдельную сборку под Mac можно только на самом Mac: Unreal не умеет
собирать игру для macOS из-под Windows, потому что для этого нужен Xcode. Кроме
того, неподписанное приложение на macOS придётся открывать через правый клик →
**Открыть**.

Что понадобится на Mac:

- **Xcode** из App Store
- **Unreal Engine 5.5** для macOS — через Epic Games Launcher, так же, как в
  разделе [Установка](#2-unreal-engine-55)

**Запустить проект без упаковки** — то же, что способ А для Windows:

```bash
cd firing-range
"/Users/Shared/Epic Games/UE_5.5/Engine/Binaries/Mac/UnrealEditor.app/Contents/MacOS/UnrealEditor" \
  "$PWD/FiringRange.uproject" -game -windowed -ResX=1280 -ResY=720
```

При первом запуске движок соберёт C++-модуль проекта под macOS — это займёт
несколько минут.

**Собрать приложение `.app`:**

```bash
"/Users/Shared/Epic Games/UE_5.5/Engine/Build/BatchFiles/RunUAT.sh" BuildCookRun \
  -project="$PWD/FiringRange.uproject" -noP4 -platform=Mac -clientconfig=Shipping \
  -build -cook -stage -pak -compressed -archive -archivedirectory="$PWD/Packaged"
```

Готовое приложение появится в `Packaged/Mac/FiringRange.app`. Если macOS пишет,
что приложение повреждено или его невозможно проверить, снимите с него
карантинный атрибут:

```bash
xattr -cr Packaged/Mac/FiringRange.app
```

> Код писался кроссплатформенным, но на macOS проект пока не собирался.
> Компилятор clang строже компилятора Visual Studio, поэтому при первой сборке
> могут понадобиться небольшие правки.

### Linux

Сборку под Linux можно сделать прямо на Windows. Для этого нужен набор
инструментов Epic для кросс-компиляции — clang под Linux той версии, которая
указана в требованиях UE 5.5. После его установки в команде упаковки
`-platform=Win64` меняется на `-platform=Linux`.

**Linux-сборка на Mac не запустится.** macOS — не Linux: у них разный формат
программ (Mach-O и ELF), разные системные библиотеки и разные графические API
(Metal и Vulkan). Для Mac нужна своя сборка — см. выше.

## Управление

| Клавиша | Действие |
|---|---|
| `W` `A` `S` `D` | Движение |
| Мышь | Обзор |
| `Shift` | Бег |
| `Ctrl` или `C` | Присесть |
| `Space` | Прыжок |
| **ЛКМ** | Огонь |
| **ПКМ** | Прицеливание |
| `R` | Перезарядка |
| `1` `2` `3` | Пистолет, дробовик, снайперская винтовка |
| Колесо мыши | Переключение оружия |
| `T` | Запустить режим на время |
| `Esc` | Пауза |

Геймпад размечен на те же действия.

Патроны пополняются проходом по ящику. Ящик исчезает только если патроны
действительно поместились — с полным резервом он останется на месте.

## Особенность проекта

**В репозитории нет ни одного авторского ассета.** Единственные бинарные файлы —
две пустые карты по 9 КБ.

Задание разрешает Blueprints или C++. Проект использует C++ целиком и идёт на шаг
дальше: в нём нет вообще никакого авторского контента — ни мешей, ни текстур, ни
материалов, ни звуков, ни анимаций, ни виджетов UMG, ни ассетов ввода, ни
геометрии уровня.

| Обычно это ассет | Здесь вместо него |
|---|---|
| Меши оружия и мишеней | Примитивы из `/Engine/BasicShapes`, собранные и покрашенные кодом |
| Материалы | Динамические экземпляры движкового `BasicShapeMaterial` |
| `InputAction`, `InputMappingContext` | Объекты, созданные через `NewObject` в рантайме |
| Меню на UMG | Виджеты Slate на C++ |
| Виджеты HUD | Рисование на Canvas в `AHUD::DrawHUD` |
| Анимации перезарядки и отдачи | Процедурная анимация трансформа оружия |
| Геометрия уровня, свет, PlayerStart | `AFRRangeBuilder`, строящий всё при старте сессии |

Причина практическая, а не эстетическая: репозиторий из чистого текста можно
прочитать, отревьюить построчно, слить ветки и посмотреть diff. С `.uasset` так
нельзя. Расплата — тир выглядит как кубики, и этот размен сделан осознанно.

Единственное исключение — два файла `.umap`. Карту движок не умеет создать из
кода при загрузке, поэтому она хранится файлом. Но внутри обеих карт **пусто** —
только ссылка на режим игры, а всё остальное появляется при запуске.

## Как это устроено

```
             UFRGameInstance                  переживает смену уровня
             (настройки, рекорд)              ────────────────────────
                     │
        ┌────────────┴─────────────┐
        │                          │
  AFRMenuGameMode           AFRRangeGameMode ─── AFRRangeBuilder
  (карта MainMenu)          (карта FiringRange)  (строит тир)
        │                          │
  AFRMenuPlayerController    AFRRangeGameState ──────────► AFRHUD
  → SFRMainMenu              (табло)                       (только читает)
      → SFRSettingsPanel            ▲
                                    │ пишет
                          ┌─────────┴──────────┐
                          │                    │
                  AFRWeaponBase          AFRTargetBase
                  (выстрелы)             (попадания, зоны)
                          │                    ▲
                    AFRProjectile ─────────────┘
                    (урон, исход полёта)
```

Один выстрел проходит через проект так:

1. `AFRCharacter` получает действие огня и вызывает `StartFire` у оружия.
2. `AFRWeaponBase` проверяет темп и магазин, тратит патрон, трассирует луч из
   камеры вперёд — чтобы узнать, что накрывает прицел, — и выпускает снаряды в
   эту точку, целясь чуть выше ровно на ту величину, на которую пуля упадёт по
   дороге.
3. Оружие сообщает, сколько снарядов покинуло ствол. Игровой режим добавляет их в
   знаменатель точности.
4. `AFRProjectile` летит и при попадании наносит урон через штатный конвейер
   повреждений движка.
5. `AFRTargetBase::TakeDamage` определяет задетую зону, сообщает о попадании,
   падает и сам планирует своё возвращение.
6. `AFRRangeGameMode` превращает зону и дистанцию в очки и пишет их в
   `AFRRangeGameState`.
7. `AFRHUD`, подписанный на табло, рисует хит-маркер.

Ни в один момент пуля не знает, что такое мишень, мишень не знает, что такое
очки, а HUD не знает, что такое оружие.

### Решения, о которых стоит знать

**Честный прицел и настоящая баллистика одновременно.** Задание требует и прицел,
точно показывающий точку попадания, и пули, подчиняющиеся физике. Это
противоречие: пуля с гравитацией падает ниже точки прицела.
`AFRWeaponBase::ComputeLaunchVelocity` его разрешает — считает время полёта по
дистанции и скорости, считает просадку за это время и наводит ствол ровно на эту
величину выше. Пуля летит по дуге и всё равно приходит в точку прицела.

**Прицел раскрывается, когда оружие менее точно.** Зазор между штрихами — это
конус разброса, спроецированный в пиксели. Он расширяется при беге и сужается при
прицеливании. Прицел постоянного размера врал бы.

**Отдача пишется в поворот контроллера в градусах**, а не подаётся через
`AddControllerPitchInput`. Ввод проходит через настройку чувствительности мыши, и
иначе игрок с высокой чувствительностью получил бы совсем другое оружие.

**У пуль свой канал коллизий.** Дробовик выпускает восемь картечин из одной точки
в один кадр. В общем канале они блокировали бы друг друга прямо на спауне.

**Мишени — это пешки.** Только в пешку может вселиться `AAIController`, а
движущимся мишеням он нужен.

**ИИ мишеней не использует навигацию.** Навигационный меш — это данные,
запечённые в ассет уровня, а у проекта нет ассета уровня, куда их печь.
Аналитическое следование по сплайну не требует данных и даёт точное, повторяемое
движение — что тренировочному тиру и нужно.

**Выстрел закрывает пуля, а засчитывает мишень.** В момент нажатия на курок
неизвестно, попадёт ли выстрел: пуля ещё летит. Поэтому `AFRProjectile` сообщает,
когда закончил полёт, — в том числе если просто истекло время. А было ли
попадание, говорит только мишень, через своё событие. По урону судить нельзя:
в Unreal любой актор по умолчанию принимает урон, и стена «принимает» пулю так
же, как яблочко.

**Кроссплатформенность с самого начала.** Переводы строк в репозитории всегда LF
(`.gitattributes`), пути в `#include` полные и в точном регистре — для
регистрозависимых файловых систем Linux и macOS. Для выхода из игры используется
`UKismetSystemLibrary::QuitGame`, а не системные вызовы, и абсолютных путей в
коде нет.

**Тир открытый.** Солнце, атмосфера и sky light в режиме реального захвата дают
корректное освещение без единого импортированного файла.

## Соответствие заданию

| Требование | Где реализовано |
|---|---|
| Меню на отдельной карте | Карта `MainMenu`, `AFRMenuGameMode`, `SFRMainMenu` |
| Кнопка Start Game | `SFRMainMenu` → `AFRMenuPlayerController::HandleStartGame` |
| Настройка чувствительности мыши | `SFRSettingsPanel`, сохраняется в `UFRGameInstance` |
| Кнопка выхода | `AFRMenuPlayerController::HandleQuitGame` |
| Точный прицел | `AFRHUD::DrawCrosshair` + `AFRWeaponBase::ComputeLaunchVelocity` |
| Отображение точности | `FFRRangeStats::GetAccuracy`, рисуется в `AFRHUD::DrawScorePanel` |
| Патроны и статус перезарядки | `AFRHUD::DrawWeaponPanel` |
| Движение персонажа | `AFRCharacter`, Enhanced Input |
| Обработка прицеливания, огня, перезарядки | `AFRCharacter::BuildInputActions` |
| Подбор патронов | `AFRAmmoPickup` |
| Отдача | `AFRWeaponBase::ApplyRecoil` и `UpdateRecoil` |
| Анимация перезарядки | `AFRWeaponBase::UpdateViewModel`, процедурная |
| Физика снарядов | `AFRProjectile` |
| Детект попаданий с обратной связью | `AFRProjectile::HandleHit`, `AFRImpactEffect` |
| Статичная мишень | `AFRStationaryTarget` |
| Движущаяся мишень с ИИ | `AFRMovingTarget` + `AFRTargetAIController` |
| Детект попаданий по мишеням | `AFRTargetBase::TakeDamage`, `ResolveHitZone` |
| Респаун мишеней по таймеру | `AFRTargetBase::HandleKnockedDown` |
| Цельная тема и освещение | `AFRRangeBuilder::BuildLighting` и палитра рядом |
| Секция статичных мишеней | `AFRRangeBuilder::BuildStationarySection` |
| Секция движущихся мишеней | `AFRRangeBuilder::BuildMovingSection` |
| Старт с заряженным оружием | `AFRWeaponBase::BeginPlay` |
| Меню паузы | `AFRPlayerController::OpenPauseMenu`, `SFRPauseMenu` |
| Рестарт из паузы | `AFRRangeGameMode::RestartRange` |
| Возврат в главное меню | `AFRPlayerController::HandleQuitToMainMenu` |
| **Бонус** — несколько стволов | `AFRPistol`, `AFRShotgun`, `AFRSniperRifle` |
| **Бонус** — продвинутый ИИ мишеней | `EFRTargetMotion`, четыре паттерна, три уровня сложности |
| **Бонус** — зоны попадания и хедшоты | `AFRTargetBase::ResolveHitZone`, очки в `AFRRangeGameMode` |
| **Бонус** — режим на время | `AFRRangeGameMode::StartTimedChallenge`, клавиша `T` |
